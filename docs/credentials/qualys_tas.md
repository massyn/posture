# Qualys TotalAppSec — credential setup

[← back to collector docs](../collectors/qualys_tas.md)

This collector can reuse the API user created for the [Qualys VMDR
collector](qualys.md). Create and activate the user there first (user
details, business unit, activation, password policy and API server URL are
all covered on that page), then add the TotalAppSec access below and set the
same values under the `QUALYS_TAS_*` environment variables.

**Unverified:** these steps follow Qualys's public documentation and have
not been checked against a live subscription. Menu labels vary between
Qualys releases, so verify each step on your own subscription.

## What the collector needs

The collector calls the WAS v3 web application and finding search APIs
(`/qps/rest/3.0/search/was/webapp` and `/qps/rest/3.0/search/was/finding`).
TotalAppSec (Web Application Scanning) does not use VMDR asset groups: access
comes from a **role** with the **API Access** permission, and visibility from
the user's **tag scope**. A web application is only visible when one of its
tags matches one of the user's scope tags.

Subscription-level OAuth clients cannot be used: Qualys does not accept them
on any Web Application Scanning endpoint.

## Assign a read-only role

You need a Manager, or a user with the Edit User permission.

* Open the **Administration** module and go to **Role Management**.
* Check whether the built-in **WAS Reader** role (or **TAS Reader**,
  depending on release) includes **API Access** under **Access
  Permissions**. If it does, use it. If not, select **Create Role**, name it
  e.g. `CCM WAS Reader`, and grant:
    * **Access Permissions**: **API Access** and **WAS** (TotalAppSec)
      module access.
    * **Web Application Permissions**: view only. Leave create, edit,
      delete, scan and purge unticked.
* Select **Save**.

Create a new role rather than adding **API Access** to the built-in one if
other users have it: editing a shared role changes the permissions of every
user who has it.

## Set the web application scope

* In **Administration** > **User Management**, edit the `CCM Read Only`
  user.
* **Roles**: add the WAS reader role from above.
* **Scope**: give the user every web application the collection should
  cover, typically **Full Scope**. If you scope by tags instead, add the tags
  carried by every web application you need; an application with none of
  those tags is invisible to the collector. A user scoped to a subset
  produces a snapshot of that subset only, with no error to say so.
* Select **Save**.

## Record the credentials

Store the following values securely. These map directly to the collector's
required config:

| Value | Config key | Environment variable |
| --- | --- | --- |
| API server URL (e.g. `https://qualysapi.qualys.com`) | `base_url` | `QUALYS_TAS_BASE_URL` |
| Username (generated by Qualys) | `username` | `QUALYS_TAS_USERNAME` |
| Password (set at first login) | `password` | `QUALYS_TAS_PASSWORD` |
