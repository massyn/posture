# SentinelOne — credential setup

[← back to collector docs](../collectors/sentinelone.md)

SentinelOne API tokens inherit whatever role the generating user holds —
they are not independently scoped at creation time, the same shape as
[Okta](okta.md). These steps create a dedicated service account with a
read-only role, so the resulting token can't be used for anything beyond
reads, rather than reusing a personal admin's token.

## Create the service account

* Log in to your SentinelOne Management Console as an administrator.
* Navigate to **Settings** > **Users**.
* Select **Actions** > **Create New User** (or the equivalent "Invite
  User" flow on your console version).
* Fill in a dedicated service account (e.g. `ccm-readonly@yourdomain.com`).
* Under **Role**, assign the built-in **Viewer** role (SentinelOne's
  read-only role — can view agents, threats, alerts, and configuration but
  cannot take response actions or change settings) at the appropriate
  scope (Account or Site, matching which tenants you want this
  integration to see).

## Generate the API token

* Sign in to the console **as the service account** — tokens inherit the
  creating account's own role/scope, so the token must be generated by
  this account, not an admin acting on its behalf.
* Navigate to the account menu (top-right) > **My User** > **Actions** >
  **Generate API Token** (exact menu wording varies slightly by console
  version — look under the user's own settings/profile page for "API
  Token").
* Set an appropriate expiry. SentinelOne API tokens expire on the
  configured schedule; expired tokens return `401 Unauthorized` on every
  call, so plan a rotation reminder rather than an indefinite token if
  your tenant's policy requires expiry.
* Copy the token value immediately — it is only shown once.

## Find your console URL

* Your management console URL is the same host you use to log in, e.g.
  `https://yourcompany.sentinelone.net`.

## Record the credentials

Store the following values securely — these map directly to the collector's
required config:

| Value | Config key | Environment variable |
| --- | --- | --- |
| Console URL | `console_url` | `SENTINELONE_CONSOLE_URL` |
| API Token | `api_token` | `SENTINELONE_API_TOKEN` |

**Caveat:** exact console navigation (menu labels for user creation and
token generation) varies across SentinelOne console versions/deployments
and was not independently confirmed against a live tenant — the **Viewer**
role and the general "token inherits creator's role" behaviour are
well-documented by SentinelOne, but verify the specific click-path in your
own console before relying on the steps above.
